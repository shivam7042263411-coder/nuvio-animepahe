# kwik-id catalogue

Read-only data for `animepahe.js`. One file per show plus a generated index.
The plugin fetches these over `raw.githubusercontent.com`; the app never sees
them.

## Schema

`index.json` (generated by the tools, never hand-edited):

```json
{
  "version": 1,
  "updated": "2026-11-18",
  "shows": [
    { "file": "horimiya.json", "title": "Horimiya", "aliases": [], "season": 1, "year": 2021 }
  ]
}
```

`<show>.json`:

```json
{
  "title": "Horimiya",
  "aliases": [],
  "season": 1,
  "year": 2021,
  "source": "animepahe",
  "session": "d8099128-...",
  "episodes": 13,
  "rows": [
    { "s": 1, "e": 1, "q": 1080, "a": "sub", "id": "R9C24C09aEgd" }
  ]
}
```

| Field | Meaning |
|-------|---------|
| `s` | app season (`1` for movies) |
| `e` | app episode (`1` for movies) |
| `q` | `1080` - the only quality stored |
| `a` | `sub` - the only audio stored |
| `id` | the part after `https://kwik.cx/e/` |

One row per episode. 720p and dubs are deliberately not stored: the plugin
never offers them, so they would only be dead weight. Every writer filters
through `writeShow` in `tools/catalogue-lib.mjs`, so a file cannot drift.

`aliases` is the escape hatch for a show whose TMDB titles differ from the
AnimePahe title: add e.g. `"Sousou no Frieren"`. Matching is exact after
folding case, punctuation and doubled letters (`Haikyu!!` = `Haikyuu!!`).

## Why no URLs

Only ids are stored. The MP4 path is derived at play time from the kwik page
the id points to. A stored URL would rot; an id has survived five years.

## Adding shows

```bash
node tools/harvest-batch.mjs            # tools/shows.txt, ~1 request/episode
node tools/merge-log.mjs <device log>   # top up from what the box watched
node tools/build-catalogue.mjs          # import ../probe/ids-*.json
```

Each tool writes the show file and rebuilds `index.json`.
